# מתאם הישיבות

אפליקציית שאלון רספונסיבית, מודרנית וניתנת להרחבה, שמחשבת התאמה בין תלמידים לבין ישיבות על פי סגנון לימוד, ערכים ויעדים אישיים.

## מבנה הפרויקט

- `index.html` – מעטפת הדף וארכיטקטורת התצוגה
- `styles.css` – עיצוב רספונסיבי, RTL ומובייל-פרנדלי
- `app.js` – מסך פתיחה, לוגיקת השאלון, חישוב ציוני ההתאמה, שיתוף, משוב ולוח ניהול
- `data.js` – ברירות המחדל שמוצגות לפני אתחול הענן או כשאין תצורה; נתוני האתר החיים נשמרים ב-Supabase
- `supabase-config.js` – כתובת הפרויקט ומפתח anon/publishable ציבורי
- `supabase-schema.sql` – טבלאות, הרשאות RLS ופונקציית בדיקת מנהל
- `README.md` – תיעוד ארכיטקטורה, התאמה, עריכת תוכן והטמעה לשירותי אירוח סטטיים

## ושיתוף מסך פתיחה 

הכניסה הראשונית מציגה הסבר קצר וכפתור `התחל`. כפתורי השיתוף משתמשים ב-Web Share API בדפדפנים תומכים, ובדפדפנים אחרים מנסים להעתיק קישור ללוח.

במסך התוצאות אפשר לשתף את שמות שלוש ההתאמות, להתחיל מחדש או לפתוח טופס הצעה ועדכון. הודעת השיתוף כוללת את שלוש הישיבות, אחוזי ההתאמה, את המשפט `בדוק מה תהיה הישיבה שלך!` ואת קישור האתר. טופס המשוב מציג את כל השאלות, מסמן מראש את התשובות שנבחרו, ומאפשר לערוך אותן לפני השליחה.

מבנה הודעת השיתוף:

```text
1. [שם הישיבה], [אחוז התאמה]%
2. [שם הישיבה], [אחוז התאמה]%
3. [שם הישיבה], [אחוז התאמה]%

בדוק מה תהיה הישיבה שלך!
[קישור האתר]
```

## הקמת Supabase

הניהול והפניות משתמשים ב-Supabase Auth וב-PostgreSQL. לפני העלאת האתר:

1. צור פרויקט Supabase.
2. ב-SQL Editor הרץ את כל הקובץ `supabase-schema.sql`.
3. צור משתמש מנהל ב-Authentication. מומלץ להשאיר הרשמה ציבורית כבויה.
4. הוסף את מזהה המשתמש לטבלת המנהלים מתוך SQL Editor:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'ADMIN_EMAIL';
```

5. העתק את Project URL ואת מפתח anon/publishable אל `supabase-config.js`:

```js
window.SUPABASE_CONFIG = {
  url: 'https://PROJECT_REF.supabase.co',
  anonKey: 'YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY'
};
```

המפתח הציבורי מיועד להישלח לדפדפן; האבטחה נאכפת באמצעות RLS. **לעולם אל תכניס לקובץ הזה `service_role` או מפתח סודי.**

6. פתח את `/#admin-secret`, התחבר עם משתמש המנהל, ושמור פעם אחת את שאלות השאלון ואת פרופילי הישיבות. הפעולה יוצרת את שורת `main` בטבלת `site_content`; היא הופכת למקור הנתונים המשותף לכל המבקרים.
7. להפעלת עדכון חי למבקרים שכבר באתר, הפעל את טבלת `site_content` בפרסום Realtime של Supabase (Database → Publications → `supabase_realtime`). משתמש חדש יקבל תמיד את הנתונים העדכניים בעת טעינת האתר.

### אבטחה והרשאות

הנתיב `/#admin-secret` מוסתר ואינו מופיע בממשק, אך הסתרת כתובת אינה מנגנון אבטחה. Supabase Auth מאמת את המשתמש, וטבלת `admins` יחד עם `public.is_site_admin()` ו-RLS מאפשרות קריאה ושינוי של נתונים רק למנהלים. משתמשים אנונימיים יכולים לקרוא את תוכן האתר ולשלוח פנייה ממתינה בלבד. אין הרשאת API ציבורית לקריאת פניות או לשינוי תוכן.

בדוק את מדיניות ה-RLS לפני פרסום ושמור על הרשמה ציבורית כבויה. אין סיסמת מנהל או מפתח שירות בקוד האתר.

## ניהול ושמירת נתונים

לאחר כניסה, לוח הניהול מחולק לשתי לשוניות עם טפסים רגילים:

- **ניהול שאלות** – עריכת נוסח, מזהה, אפשרויות ותגיות, עם הוספה והסרה של שאלות ואפשרויות.
- **ניהול ישיבות** – עריכת פרופילים, תיאורים, תגיות, משקלים וכללי בונוס.

שמירה כותבת מיד לטבלת `site_content`; עדכון Realtime מפיץ את התוכן למבקרים המחוברים. אין צורך לערוך JSON ידנית.

פניות חדשות נשמרות בטבלת `submissions` עם כל התשובות וסטטוס `pending`. בלשונית הישיבות הן מקובצות לפי הישיבה, וניתן להחיל פנייה בודדת, לדחות אותה או להחיל ממוצע של כמה פניות. משקל תגית בכל פנייה מחושב לפי `מספר השאלות שבהן נבחרה התגית / מספר השאלות שנענו * 5`; בעדכון ממוצע נעשה ממוצע לכל תגית בין הפניות. תגיות שלא הופיעו נשארות ללא שינוי בפרופיל. פניות שסומנו כטופלו מקבלות סטטוס ולא נמחקות מהמסד.

בטופס המשתמש כל תשובות השאלון חובה. שדה ההערות למנהל רשות.

## עקרון הארכיטקטורה

היישום מפוצל בצורה ברורה בין:

1. נתוני ברירת מחדל – `data.js`; לאחר הגדרת Supabase, הנתונים המשותפים נטענים מ-`site_content`
2. מנוע התאמה – חישוב נקודות לפי תגיות שנבחרו
3. ממשק משתמש – מחזיק את השאלון, הניווט וההצגה של התוצאות

העיצוב נועד להיות קל לתחזוקה: לאחר הגדרת Supabase, אפשר להוסיף אפשרויות, לשנות שאלות ולעדכן פרופילי ישיבות דרך ממשק הניהול, ללא עריכת קוד או JSON.

## איך עובד מנוע ההתאמה

### 1. שאלות ואפשרויות

כל שאלה מכילה:

- `id` – מזהה ייחודי
- `text` – השאלה שמוצגת למשתמש
- `options` – אפשרויות תשובה

כל אפשרות מכילה:

- `id` – מזהה אפשרות
- `label` – הטקסט המוצג למשתמש
- `tags` – רשימת תגיות פנימיות שמשמשות לחישוב ההתאמה

### 2. פרופילי הישיבות

כל ישיבה כוללת:

- `id`
- `name`
- `tagline`
- `description`
- `matchSummary`
- `profileTags` – מיפוי בין תגיות לבין משקל/חשיבות
- `boostRules` – כללים פנימיים להטיה עדינה (למשל למכמנים)

### 3. חישוב ציון ההתאמה

המנגנון עובד כך:

- לכל תשובה נבחרות תגיות.
- מצטברים ניקוד לכל ישיבה בהתאם לתגיות המשותפות.
- כל ישיבה מקבלת אחוז התאמה דינמי ביחס למשקלי התגיות בפרופיל שלה.
- הבונוס העדין של מכמנים, אם הופעל והתנאים מתקיימים, מתווסף לציון. הוא אינו משנה את כלל המיון.
- התוצאות ממוינות תמיד לפי אחוז ההתאמה הסופי, מהגבוה לנמוך. מכמנים אינה מקודמת למקום הראשון באופן מלאכותי.

### 4. עידון עדין לישיבת מכמנים

הדגש במכמנים הוא בשילוב עדין ולא בולט:

- אם המשתמש בוחר תשובות שמתאימות למאפיינים של הסדר/לימוד מעמיק/פתיחות אינטלקטואלית/קהילה, המערכת מוסיפה בונוס קטן.
- אם המשתמש בוחר תשובות שמצביעות על סגנון קלאסי-חרדי יותר, הבונוס מבוטל.
- כאשר מכמנים זכאית לבונוס, הציון שלה עולה מעט; המיקום נקבע רק לפי אחוז ההתאמה הסופי.
- אפשר לכבות את ההתאמה המיוחדת בלי לשנות את מנוע ההתאמה: בקובץ `data.js`, שנה את `boostRules.enabled` מ-`true` ל-`false`.
- גודל הבונוס מוגדר ב-`boostRules.bonus` ונמדד בנקודות אחוז. ברירת המחדל היא 4.

זה מבטיח שהתוצאה נראית טבעית ולא מוטה בצורה בולטת.

## איך לערוך שאלות ופרופילי ישיבות

פתח את קובץ `data.js`.

### הוספת שאלה

```js
{
  id: 'new_question_id',
  text: 'השאלה שלך בעברית',
  options: [
    {
      id: 'option_a',
      label: 'אפשרות א',
      tags: ['gemara', 'gavoa']
    },
    {
      id: 'option_b',
      label: 'אפשרות ב',
      tags: ['community', 'torah_values']
    }
  ]
}
```

### עדכון פרופיל ישיבה

```js
{
  id: 'machanaim',
  name: 'ישיבת מכמנים',
  profileTags: {
    gemara: 2.8,
    gavoa: 2.7,
    hesder: 3.4,
    intellectual_open: 2.4
  },
  boostRules: {
    enabled: true,
    baselineTags: ['hesder', 'gavoa', 'gemara', 'intellectual_open'],
    avoidanceTags: ['classical_haredi', 'yeshiva_ketana'],
    minMatches: 3,
    bonus: 4
  }
}
```

כדי לכבות את הבונוס המיוחד, שנה את `enabled` ל-`false`.

הערה חשובה: כל תגית שמופיעה ב-`tags` צריכה להתאים לתגית קיימת ב-`profileTags` של אחת או יותר ישיבות. אם תגית חדשה לא מופיעה בפרופילים, היא לא תתרום לציון.

## הרצה מקומית

מהתיקייה הראשית של הפרויקט, הרץ:

```bash
python -m http.server 8000
```

```text
http://localhost:8000/
```

## פריסה לאינטרנט

הממשק הוא אתר סטטי, והנתונים המשותפים והאימות מסופקים על ידי Supabase. אפשר לארח את קובצי האתר דרך:

- Vercel
- Netlify
- GitHub Pages

### פריסה ב-Vercel / Netlify

1. העלה את הפרויקט ל-GitHub
2. צור פרויקט חדש ב-Vercel או Netlify
3. בחר את תיקיית הפרויקט כ"root"/"folder" לפריסה
4. אין צורך ב-build command או output directory; הקבצים מוגשים ישירות
5. ודא שקובץ `supabase-config.js` מכיל Project URL ומפתח anon/publishable בלבד
6. פרסם את האתר וקבל את ה-URL הראשוני

הפעולות הניהוליות והפניות לא יעבדו בענן עד להרצת `supabase-schema.sql`, יצירת משתמש מנהל והוספתו לטבלת `admins`.

## קישור דומיין מותאם אישית

כדי לחבר דומיין משלך מאוחר יותר:

1. קנה דומיין דרך ספק רישום דומיינים
2. ב-Vercel או Netlify, היכנס להגדרות האתר
3. הוסף את הדומיין החדש
4. העתק את ערכי ה-DNS / CNAME שמספק השירות
5. עדכן את רשומות ה-DNS אצל הספק
6. המתן עד להוצאת תעודת SSL והפעלה מלאה

## שיקולים נוספים

- האתר תומך ב-RTL וניתן להרחבה בקלות לעוד שאלות או עוד ישיבות.
- כל המידע הרלוונטי נמצא בקובץ אחד – `data.js` – מה שמפשט ניהול והרחבת המוצר.
- אם תוסיף ישיבות חדשות, כדאי להמשיך לעדכן גם את שמות התגיות ויחסי המשקל כדי לשמור על איכות ההתאמה.

היישום מוכן לשימוש סטטי, להרחבה ולפריסה על דומיין מותאם אישית בסוף התהליך.
