# מתאם הישיבות

אפליקציית התאמה בעברית שממליצה על ישיבות לפי תשובות לשאלון. תוכן השאלון ופרופילי הישיבות נטענים מ-Supabase, והצעות ועדכונים נשמרים בענן כדי שיהיו זמינים למבקרים ולמנהלים מכל מכשיר.

## הפעלה מקומית

1. הגדירו ב-`supabase-config.js` את כתובת פרויקט Supabase ואת מפתח ה-publishable/anon הציבורי שלו. אין להכניס לקובץ מפתח `service_role` או סוד אחר.
2. הגישו את תיקיית הפרויקט דרך שרת HTTP מקומי או אירוח סטטי. לדוגמה, אפשר להשתמש בשרת Live Preview/Live Server מתוך VS Code.
3. פרסמו את האתר דרך HTTPS בפרודקשן. שיתוף מקורי והעתקה ללוח תלויים בתמיכת הדפדפן ובהקשר מאובטח.

אין שלב build או התקנת חבילות: ספריית Supabase נטענת דרך CDN בקובץ `index.html`.

## הקמת Supabase

1. צרו פרויקט Supabase והפעילו ספק התחברות Email/Password תחת Authentication.
2. הריצו את כל הקובץ `supabase-schema.sql` ב-SQL Editor של הפרויקט. הסקריפט יוצר את טבלאות התוכן, המנהלים, הפניות והאנליטיקה, את מדיניות ה-RLS, ואת פונקציות האימות והסטטיסטיקה. אפשר להריץ אותו שוב בפרויקט קיים; עמודות הפרמטרים והפניות החדשות מתווספות באופן תואם.
3. צרו משתמש מנהל דרך Supabase Authentication, ואז הוסיפו אותו לרשימת המנהלים דרך SQL Editor, עם מזהה המשתמש שמופיע ב-Authentication:

   ```sql
   insert into public.admins (user_id)
   values ('UUID-OF-THE-AUTH-USER');
   ``` 

4. פתחו את האתר והיכנסו לכתובת `#admin-secret`. התחברו עם חשבון המנהל, שמרו את השאלות או פרופילי הישיבות כדי לאתחל את שורת `site_content` בענן, ומשם והלאה השינויים משותפים לכל המבקרים.
5. כדי לקבל עדכוני תוכן בזמן אמת בלשוניות פתוחות, ודאו שטבלת `site_content` כלולה בפרסום `supabase_realtime` בפרויקט Supabase. הטעינה הראשונית והשמירה בענן פועלות גם ללא Realtime.

### אימות הצעות ועדכונים

- הצעת ישיבה חדשה נבדקת מול שמות הישיבות ושמותיהן הקצרים בתוכן הענן בזמן ההקלדה. בדיקת מסד נתונים נוספת לפני השמירה חוסמת שם שכבר קיים.
- עדכון מחייב בחירה מפורשת של ישיבה מתוצאות החיפוש. הבקשה נשלחת עם מזהה הישיבה, ומסד הנתונים דוחה בקשה ללא מזהה קיים.
- תשובות השאלון נבדקות מול השאלות והאפשרויות העדכניות שבענן.
- מנהלים רואים הצעות שינוי לפי פרמטר תחת כל ישיבה, יכולים לקבל כל שינוי בנפרד, לקבל את ממוצע השינויים או לדחות את כל ההצעות לישיבה. פרמטרים מנוהלים בלשונית ייעודית; הוספת פרמטר נותנת לפרופילי הישיבות ערך התחלתי 5 בסולם 1–10.
- בכרטיס הישיבה מנהלים עורכים שם קצר, תיאור מלא, אזור גאוגרפי, קבוצת אזור וערכי פרופיל 1–10. קבוצת האזור משמשת גם להעדפת האזור בשאלון ולחיזוק ההתאמה.
- לשוניות הניהול כוללות שאלות, ישיבות, פרמטרים וסטטיסטיקה. הסטטיסטיקה נשמרת כנתונים מצטברים בלבד: מונים, ציונים וצבירות אנונימיות של ערכי הפרופיל; לא נשמרות תשובות, פרטי משתמש, כתובת IP, מזהה דפדפן או רשומות נפרדות עם חותמות זמן. כל השלמה נספרת בנפרד.
- לשונית הסטטיסטיקה מציגה דירוגים לפי ישיבה והתפלגות אינטראקטיבית של ערכי הפרופיל בסולם 1–10. איפוס סטטיסטיקה ושחזור נתוני ברירת מחדל מאפסים גם את צבירות ההתפלגות.

יש להריץ את `supabase-schema.sql` ב-SQL Editor לאחר כל שינוי בסכמת האנליטיקה, ובפרט כדי להפעיל את צבירות התפלגות הפרמטרים.

## שיתוף

שיתוף התוצאות יוצר תמונת PNG דינמית מתוך אזור התוצאות ומצרף את הטקסט „אלו הישיבות שיצאו לי, בדוק את שלך” ואת כתובת האתר. בדפדפנים התומכים בשיתוף קבצים התמונה נשלחת בתפריט השיתוף המקורי; אחרת התמונה מורדת והקישור משותף או מועתק ללוח. שיתוף דף הבית משתמש ב-Web Share API של הדפדפן. `share_plus` הוא תוסף Flutter ואינו מתאים לאפליקציית הווב הזו.
