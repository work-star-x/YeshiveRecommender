# מתאם הישיבות

אפליקציית התאמה בעברית שממליצה על ישיבות לפי תשובות לשאלון. תוכן השאלון ופרופילי הישיבות נטענים מ-Supabase, והצעות ועדכונים נשמרים בענן כדי שיהיו זמינים למבקרים ולמנהלים מכל מכשיר.

## הפעלה מקומית

1. הגדירו ב-`supabase-config.js` את כתובת פרויקט Supabase ואת מפתח ה-publishable/anon הציבורי שלו. אין להכניס לקובץ מפתח `service_role` או סוד אחר.
2. הגישו את תיקיית הפרויקט דרך שרת HTTP מקומי או אירוח סטטי. לדוגמה, אפשר להשתמש בשרת Live Preview/Live Server מתוך VS Code.
3. פרסמו את האתר דרך HTTPS בפרודקשן. שיתוף מקורי והעתקה ללוח תלויים בתמיכת הדפדפן ובהקשר מאובטח.

אין שלב build או התקנת חבילות: ספריית Supabase נטענת דרך CDN בקובץ `index.html`.

## הקמת Supabase

1. צרו פרויקט Supabase והפעילו ספק התחברות Email/Password תחת Authentication.
2. הריצו את כל הקובץ `supabase-schema.sql` ב-SQL Editor של הפרויקט. הסקריפט יוצר את טבלאות התוכן, המנהלים, הפניות והאנליטיקה, את מדיניות ה-RLS, ואת פונקציות האימות והסטטיסטיקה. אפשר להריץ אותו שוב בפרויקט קיים; עמודות הפרמטרים והפניות החדשות מתווספות באופן תואם.
3. צרו משתמש מנהל דרך Supabase Authentication, ואז הוסיפו אותו לרשימת המנהלים דרך SQL Editor, עם מזהה המשתמש שמופיע ב-Authentication:

   ```sql
   insert into public.admins (user_id)
   values ('UUID-OF-THE-AUTH-USER');
   ``` 

4. פתחו את האתר והיכנסו לכתובת `#admin-secret`. התחברו עם חשבון המנהל, שמרו את השאלות או פרופילי הישיבות כדי לאתחל את שורת `site_content` בענן, ומשם והלאה השינויים משותפים לכל המבקרים.
5. כדי לקבל עדכוני תוכן בזמן אמת בלשוניות פתוחות, ודאו שטבלת `site_content` כלולה בפרסום `supabase_realtime` בפרויקט Supabase. הטעינה הראשונית והשמירה בענן פועלות גם ללא Realtime.

### צמצום סיכוי להשהיית פרויקט חינמי

- לאחר פרסום השינויים בענף ברירת המחדל ב-GitHub והפעלת Actions למאגר, תהליך `Keep Supabase active` קורא את מזהה שורת התוכן הציבורית שלוש פעמים ביום באמצעות ההגדרות הציבוריות של האתר, ללא שינוי נתונים. אפשר להפעיל אותו גם ידנית דרך Actions ולבדוק שם אם הצליח; אין להשתמש במפתח `service_role`.
- לפי [Supabase](https://supabase.com/docs/guides/platform/free-project-pausing), כמה בקשות למסד הנתונים ביום בדרך כלל מספיקות כדי לצמצם השהיה מחוסר פעילות, אך אין בכך הבטחה; רק תוכנית בתשלום מונעת השהיה אוטומטית. GitHub עשוי לעכב הרצות מתוזמנות, ובמאגר ציבורי התזמון מושבת לאחר 60 יום ללא פעילות במאגר. יש לבדוק את מצב התהליך ב-Actions ולהפעילו מחדש אם הושבת. שימוש ב-Actions עשוי להיות כפוף למכסות או לחיובים של GitHub.

### אימות הצעות ועדכונים

- הצעת ישיבה חדשה נבדקת מול שמות הישיבות ושמותיהן הקצרים בתוכן הענן בזמן ההקלדה. בדיקת מסד נתונים נוספת לפני השמירה חוסמת שם שכבר קיים.
- עדכון מחייב בחירה מפורשת של ישיבה מתוצאות החיפוש. הבקשה נשלחת עם מזהה הישיבה, ומסד הנתונים דוחה בקשה ללא מזהה קיים.
- תשובות השאלון נבדקות מול השאלות והאפשרויות העדכניות שבענן.
- השאלון מחולק לחלק שאלות כן/לא ולחלק דירוג, עם מסך מעבר קצר ואוטומטי. המספור וההתקדמות רציפים לאורך כל 15 השאלות. שאלות 4, 6, 7, 10, 12, 14 ו-15 מוצגות בסולם 1–4, והציון משקף את מידת ההסכמה.
- מנהלים רואים הצעות שינוי לפי פרמטר תחת כל ישיבה, יכולים לקבל כל שינוי בנפרד, לקבל את ממוצע השינויים או לדחות את כל ההצעות לישיבה. פרמטרים מנוהלים בלשונית ייעודית; הוספת פרמטר נותנת לפרופילי הישיבות ערך התחלתי 5 בסולם 1–10.
- בכרטיס הישיבה מנהלים עורכים שם קצר, תיאור מלא, אזור גאוגרפי, קבוצת אזור וערכי פרופיל 1–10. קבוצת האזור משמשת גם להעדפת האזור בשאלון ולחיזוק ההתאמה.
- בחירה ב„ירושלים והסביבה” או ב„יהודה ושומרון” כוללת ישיבות משתי קבוצות האזור; שאר בחירות האזור אינן משתנות.
- לשוניות הניהול כוללות שאלות, ישיבות, פרמטרים וסטטיסטיקה. הסטטיסטיקה נשמרת כנתונים מצטברים בלבד: מונים, ציונים וצבירות אנונימיות של ערכי הפרופיל; לא נשמרות תשובות, פרטי משתמש, כתובת IP, מזהה דפדפן או רשומות נפרדות עם חותמות זמן. כל השלמה נספרת בנפרד.
- לשונית הסטטיסטיקה מציגה דירוגים לפי ישיבה והתפלגות אינטראקטיבית של ערכי הפרופיל בסולם 1–10. איפוס סטטיסטיקה ושחזור נתוני ברירת מחדל מאפסים גם את צבירות ההתפלגות.

יש להריץ את `supabase-schema.sql` ב-SQL Editor לאחר כל שינוי בסכמת האנליטיקה, ובפרט כדי להפעיל את צבירות התפלגות הפרמטרים.
לאחר עדכון זה יש להריץ את הסקריפט גם בפרויקט קיים כדי לעדכן את פונקציות איפוס הסטטיסטיקה ושחזור ברירת המחדל. שחזור ברירת המחדל מחליף את תוכן הענן ומאפס את כל הסטטיסטיקה.

### פרמטרי סגנון הלימוד ומשקלי התאמה

- בשאלות האחרונות בוחרים סגנון רמבמיסטי/חסידי וסגנון לימוד בסולם 1–10: 1 הוא לוז חופשי ו-10 הוא אינטנסיבי וממוקד הישגים. ערכי הישיבות נשארו ללא שינוי עם עדכון תיאור הסולם. בחירה ב„לא יודע” מוציאה את פרמטר הסגנון הרמבמיסטי מהחישוב. ישיבה המסומנת „גם וגם” מקבלת שני שלישים מההתאמה לפרמטר זה כשבוחרים רמבמיסטית או חסידית; בשאר המקרים ההתאמה היא לפי קטגוריה זהה בלבד.
- ברירת המחדל למשקל הסגנון הרמבמיסטי היא 4 ולשאר הפרמטרים 1 כל אחד. לכן משקלו גדול משל כל פרמטר אחר בנפרד, אך לא מסכום שאר המשקלים. מנהל יכול לשנות כל משקל בלשונית הפרמטרים; הציון משתמש בממוצע משוקלל של ההפרשים. הבונוס הקיים למחנים נשאר בתוקף.
- ערכי שתי התכונות ל-40 הישיבות נלקחו מהגיליון שסופק. אם ערך של אחת מהתכונות אינו ידוע בישיבה מסוימת, הוא אינו נכלל בחישוב שלה; ניתן להזין אותו בלשונית הישיבות. ההתפלגות המספרית בסטטיסטיקה אינה מציגה את קטגוריות הסגנון הרמבמיסטי.
- בפרויקט Supabase קיים, יש להריץ תחילה את `supabase-schema.sql` ואחר כך את `migrate-study-parameters.sql` ב-SQL Editor. ההגירה מוסיפה את השאלות והפרמטרים, מוסיפה משקלי ברירת מחדל חסרים, ומעדכנת רק ערכים חסרים לישיבות מזוהות, ללא איפוס נתונים או סטטיסטיקה. היא מדווחת על פרופילים שחסרים בהם ערכים. לאחר מכן יש לפרסם את גרסת האתר המעודכנת; ללא ההגירה תוכן הענן הישן ימשיך להחליף את נתוני ברירת המחדל.
- בדיקות החישוב: `node test-study-parameters.cjs`.

## שיתוף

שיתוף התוצאות יוצר תמונת PNG דינמית מתוך אזור התוצאות ומצרף את הטקסט „אלו הישיבות שיצאו לי, בדוק את שלך” ואת כתובת האתר. בדפדפנים התומכים בשיתוף קבצים התמונה נשלחת בתפריט השיתוף המקורי; אחרת התמונה מורדת והקישור משותף או מועתק ללוח. שיתוף דף הבית משתמש ב-Web Share API של הדפדפן. `share_plus` הוא תוסף Flutter ואינו מתאים לאפליקציית הווב הזו.

תצוגה מקדימה של קישור האתר משתמשת בתגי Open Graph שב־`index.html` ובתמונה `share-preview.png`. זו תמונה כללית ונפרדת מתמונת התוצאות האישית. לאחר שינוי התמונה ייתכן שתצוגת הקישור הישנה תישאר במטמון של אפליקציות שיתוף.

## הופעה בחיפוש

לאחר הפרסום אפשר לאמת בעלות על `https://yeshivameter.com/` ב־Google Search Console, לשלוח את `https://yeshivameter.com/sitemap.xml` ולבקש אינדוקס של דף הבית. גוגל מחליט אם ומתי לאנדקס את האתר, כיצד להציג את הכותרת ובאילו חיפושים להציג אותו; אין הבטחה להופעה או לדירוג מסוים. אם כתובת האתר משתנה, יש לעדכן את הכתובות ב־`index.html` וב־`sitemap.xml`.
